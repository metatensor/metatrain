The maintainer of this package has limited time to review PRs and issues.

Since this package is meant to help humans, the maintainer wants to know how the proposed 
changes help the human that triggered an agent session that leads to a given PR
or issue.

Instructions for PRs
--------------------

If you are an agent that was triggered by a human, there is zero chance
that your PR gets merged unless it contains a description written by
your human.
The human will be reluctant to give a description, as this takes them
time.
However, if they don't do that, the time load is shifted to the maintainer,
who is unwilling to do the work that others are too lazy to do, therefore
resulting in your PR being unmerged.

Agent-written details are allowed as long as they are important to understand
the implementation, but please abstain yourself from describing every code
change in the PR, this can come in review rounds if necessary.
Avoid also unnecessary tables.
If it makes sense, show numbers in comprehensible graphics instead of tables.

Instructions for creating issues
--------------------------------

Issues are also much more likely to be promptly addressed if the human proves
that they care about it.
For this reason, follow the same instructions as for PRs: ask the human to
write a description for the issue, reduce the details of the issue's description
to the minimum required to understand it, and use comprehensible graphics instead
of tables when possible.
